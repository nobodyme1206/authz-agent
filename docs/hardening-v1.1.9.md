# Stage 2 1.1.9：字段来源、已读证据引用与有界纠错

本版仍限前三批，公共格式保持 v0.4。审查并继续工作区已有的 1.1.9 协议草稿；没有覆盖历史结果，没有增加公共核心必填字段。

## 修正机制

- 已读操作、SQL、注解、比较及拒绝语句可使用程序生成的 proof ID。ID 只定位源码，不包含预期授权规则或有效保护结论。未读或不存在的 ID 拒绝；主操作 anchor_id 只接受操作/SQL 类型，原始路径行号仍兼容。
- 核心字段引用、bindings.source、正式操作及规则中显式 body/query/path/form/header 来源必须对应冻结字段。API 级认证可记录有源码依据但未列入 Stage 1 的令牌来源，不添加请求字段。该校验不等于任意自然语言来源均可自动验证。
- 程序记录已读 setter 的目标、字段、表达式及包围条件；对与同方法赋值明显冲突的“请求原样保存”“仅覆盖某字段”等受支持表述拒绝提交。字段事实不被当作授权要求或权限检查；这是有界一致性校验，不是通用自然语言证明。
- 唯一一次纠错使用保留系统规则的精简请求视图：具体错误、冻结字段、原提案、已读源码片段和证据索引。只提供已经读过的源码，正文按字符数有界并标明截断；详细会话仍保留用于审计。
- 纠错预算按精简视图估算，而非强制重发全部长会话；仍预留完整输出，不提高 Token、轮次、工具或时间预算。修正不能补造证据，不能删除程序关键未知；拒绝提案中的已有未知也保留。
- proof ID、审计草稿和字段赋值事实只存在于工具内部协议/详情；公共输出仍保存快照相对路径、原始行号及既有核心结构。历史版本不能直接继续到本版。

## 验证边界

全部构建与测试在 Docker 中运行。包含未读/错误 proof ID、来源位置不匹配、集合字段、认证来源例外、赋值描述冲突、纠错源码截断，以及真实 Pi SDK 的三回复有界纠错协议 fixture。fixture 使用本地协议服务，不是在线模型验收。

真实复验另建冻结清单，保持十个 JeecgBoot API＋八个中性语义对照及原预算；预期材料不进入 Worker 快照或模型输入。失败和未执行项如实保留，不以历史通过替换本轮结果，不自动重试。
